# 0022. UI feedback and navigation

Status: Accepted · 2026-10-31

## Context
With every flow working end to end, a pass through the app (docs/ui-todo.md) found gaps in how it feels to use: Sign out sat below a long page, filters scrolled away, nothing showed that a slow call was under way, a profile opened scrolled down if the directory had been, Next left you at the bottom of the new page, forms dropped typed changes without asking, and long dropdowns (28 job titles) had no search.

## Decision
- **The window scrolls, the sidebar doesn't.** The sidebar is `sticky` at full height, so the user and Sign out are always at its foot. The page keeps scrolling in the window (not in its own box), so the browser and React Router can restore it.
- **Scroll restoration** (React Router's `ScrollRestoration`): a new page opens at the top, Back and Forward return to where you were. Filter and option changes on the directory and Insights pass `preventScrollReset`, because they show the same page with other rows. Changing the directory's page scrolls to the top, since Next is at the bottom.
- **Sticky filters** on the directory (with its count line) and Insights. The title scrolls away to save height on a laptop. A line and a shadow appear only once the bar is stuck.
- **A top loading bar, NProgress** (as in Next.js apps), in an orange gradient with a glow at its leading edge (styled in index.css with our tokens; nprogress.css isn't imported). It runs on every page, sign-in included, whenever the app loads something: a page's code (Insights is a lazy route), a request something on screen is waiting for, or a save. Every request goes through TanStack Query, so its fetching and mutating counts stand in for "fetch events"; a prefetch has no observer, so it doesn't show the bar. It starts at once (a fast answer is a short sweep), trickles up to 6% every 200 ms, then fills and fades. A first version was hand-written and appeared only after 150 ms, so locally (50–90 ms answers) it was rarely seen; the product owner asked for NProgress itself, always visible.
- **Headline numbers roll in once** (Insights tiles, budget tiles, the directory count): the digits roll up from zero like an odometer (NumberFlow) the first time each number shows after the app loads or a hard refresh. Coming back to the page or changing a filter shows the new number straight away. A first version counted up on every load and filter change, re-rendering the formatted text each frame, so the width jumped and rupees switched from lakh to crore on the way; the product owner found it busy. Now the number rolls in its final unit ("₹0 Cr" to "₹6,021.83 Cr"), from the same formatting parts as the plain text (`compactMoney`), so it ends exactly as the figure reads elsewhere. Screen readers get a plain copy of the final value, and the motion is skipped when the OS asks for reduced motion.
- **Insights loads on demand** (a lazy route), so other pages don't download the charting library. The current page stays on screen, with the loading bar, until it's ready. The main bundle went from about 1.1 MB to 770 KB (with the new dependencies below).
- **The whole directory row opens the profile**, with the name kept as a real link for the keyboard and new tabs. A pointer resting on a row for 100 ms prefetches the profile and timeline, so it usually opens without a skeleton.
- **Forms ask before losing changes** (React Router's `useBlocker` plus the browser's own prompt on reload). The edit form's Save is disabled until something changes. The edit page shows the cached employee, not editable, while it loads the latest version (ADR 0017), instead of a skeleton.
- **Searchable pickers** for job titles and departments (shadcn's Command, built on `cmdk`), in the forms, the promotion dialog and the filters. Matching is "contains", not cmdk's fuzzy default, which offered Marketing and Design for "eng".
- **Smaller fixes:** placeholders shaped like the real cards and tables; the last-working-day picker limited to the hire date or latest salary change through today; the API's messages write dates the way the UI does ("8 Sep 2022"); peer averages and medians in whole rupees; the salary dialog keeps its content through the closing animation.

## Options considered
- **`<main>` as its own scroll box.** Also keeps the sidebar in place, but the browser can't restore the scroll position, and sticky offsets get harder.
- **Scroll positions keyed by path.** Keeps filter changes in place without touching the filter hooks, but opening a page from the sidebar brought back where you last left it instead of its top. Found in the browser check and replaced.
- **A hand-written loading bar.** About 50 lines and no dependency, but NProgress is the look people know, and its trickle is already tuned.
- **Counting up by hand** (requestAnimationFrame, formatting every frame). No dependency, but the width jumps as digits are added and the unit changes mid-count. NumberFlow takes a prefix and suffix, so it can keep our lakh and crore.
- **Rolling on every change.** Feedback that a filter applied, but busy on a page HR clicks around in; the dimmed "refreshing" state and the loading bar already say it.
- **Fixing the filter row and title together.** About 140 px always taken on a laptop screen.

## Consequences
- Good: the app shows what it's doing, keeps your place, and doesn't lose typing.
- Cost: three new dependencies (`cmdk`, `nprogress`, `@number-flow/react`). nprogress hasn't had a release since 2015, but it's small and stable. The main bundle is still over Vite's 500 KB warning, so more routes could be loaded on demand.
- Cost: the bar shows for background refreshes too (TanStack Query refetches when the window regains focus), a short sweep each time.

## Updates
- **2026-11-01, the rest of the UI to-do list** (docs/ui-todo.md is now done):
  - **Phones get a top bar.** Below 768 px (Tailwind's `md`) the sidebar becomes a sticky top bar with the brand and a menu button. The menu, a sheet from the left, holds the same links, the theme switch and Sign out, and closes when a page is picked; focus then goes to the new page's heading (below), not back to the menu button. The filters aren't sticky on a phone: they wrap to four rows there, a third of the screen. A first version kept them under the top bar, and the rows had little room left.
  - **Breadcrumbs on nested pages** (Employees › Asha Rao › Edit) instead of a single back link, so each level is one click away. The not-found and error states of those pages have them too.
  - **Focus moves to the new page's heading** after navigating, so a screen reader announces the page and Tab carries on from its top. Not on the first load, and not when the page has already focused something (a form's first field).
  - **Every page but the directory loads on demand** (the directory is where you land after signing in, and the sign-in page is lazy too). The main bundle went from about 770 KB to 270 KB, under Vite's warning.
  - **A calendar date picker** for hire date and last working day (`react-day-picker`, the library shadcn's Calendar wraps, styled with our tokens through its CSS variables). It looks the same in every browser, shows the date as the app does ("31 Oct 2026"), greys out days outside the allowed range, and has month and year dropdowns to reach a hire date years back.
  - **Errors that don't sit next to a field read as sentences:** "Lock version is required." rather than "is required" (`errorSentences`). A page can word a field its own way ("The last working day can't be…").
  - **The ★ list has Change salary on each row**, for HR acting on an underpaid case; the dialog loads that employee when it opens. A salary change now also refreshes Insights and Budgets, whose figures it moves.
  - **One wording for messages:** success toasts name who or what changed ("Asha Rao's salary changed to ₹30,40,176.00", "Engineering's 2026 budget set to …"), and edit conflicts all say "Someone else changed this … while this was open", then what to do.
  - **Dates read "8 Sep 2022" everywhere.** The browser's en-GB format writes "Sept", while the API's messages say "Sep", so the client spells out its own month names.
  - **The segment table fits a laptop without scrolling sideways.** All ten columns need about 1,050 px, and a 1,440 px screen gives the card about 1,100. Its figures are now in whole units (they sum up many salaries, like the dialog's peer figures), and columns give way as the card narrows: Lowest and Highest first (one outlier sets them), then the 25th and 75th percentiles, then the average. The thresholds are container queries on the card, so the sidebar and a phone are handled alike. Checked at 1,440, 1,280 and 1,024 px in every grouping. On a phone the group, people, median and payroll still scroll sideways a little. A first version hid Lowest and Highest below a 1,280 px window; measured, the table still scrolled at every laptop width.
  - Considered: shadcn's Calendar component (a wrapper around the same library that restyles each part with classes; the library's own stylesheet plus our tokens is less code to own); a card per row for the segment table on narrow screens (more code, and you can no longer compare down a column); window breakpoints instead of container queries (the sidebar takes 240 px from 768 px up, so the space the card gets doesn't grow with the window); keeping the native date input (no dependency, but it differs per browser and can't show our date format).
  - Cost: one more dependency (`react-day-picker`), downloaded only with the employee pages.
- **2026-11-01, every table on a phone:** a check at 375 px found no page scrolling sideways, but the wide tables scrolled inside their cards. The directory showed code, name and half a job title, with the salary out of sight. Budgets hid how much was used and the Change button, and the ★ list hid the difference.
  - **Every table now drops columns as its card narrows**, the way the segment table already did: container queries with thresholds measured from each column's width, so the sidebar and a phone are handled alike. What stays on a phone: name and salary in the directory; the department, how much of its budget is used, and its buttons in Budgets (the buttons stack and the status wraps); who and how far from the median in the ★ list; the reason and what it added to yearly pay in pay changes; the group and its median in the segment table, whose long job titles wrap. Checked at 375, 414, 768, 1,024, 1,280 and 1,440 px: no table scrolls sideways, and a 1,440 px laptop still shows every column.
  - On a phone the ★ list has no Change salary button; the name opens the profile, which has it.
  - **The budget counts share a row** below laptop width, instead of three full-width tiles one under another.
  - **A tab left open across a deploy reloads instead of failing.** With pages loading on demand, an open tab asks for the old build's page files, which a deploy removes, and opening a page showed the error screen. On Vite's `vite:preloadError` the app now loads the page being opened afresh, at most once a minute so a really broken file doesn't loop. Checked against a production build: a tab from one build opened Insights from the next.
  - Considered: a card per row on a phone (more code for each table, and you can no longer compare down a column); keeping sideways scrolling with the first column pinned (every column stays, but most of each row is off-screen).
